# Architecture and decisions

## Current physical modules
- `core-domain`: pure Kotlin/JVM models, longest dictionary-match trie (Unicode code points), scheduler, basic tone sandhi, deterministic sprint distribution, YIN-inspired F0 engine and tests.
- `app`: Compose Material 3, AndroidViewModel, coroutines, native SQLiteOpenHelper, shared preferences, SAF + internal private files + PdfRenderer, Android AudioRecord/AudioTrack/TTS. No internet permission. Small alpha starts with two Gradle modules, not 17 empty modules. Feature boundaries currently files/functions; split once integration is stable.

Decision: use native SQLite rather than Room/Hilt temporarily to reduce unverified compiler/plugin dependencies. This is a deliberate deviation, not full Clean Architecture: UI currently calls a ViewModel that owns store and media dependencies. Migrate to Room with checked migration and DI before large datasets. Dictionary currently in memory (30 entries); production must use indexed FTS/pagination and disk-backed trie. No migration yet because schema version 1 only; onUpgrade rejects unsupported migration rather than destructive fallback. UI strings currently Russian; resource localization pending. No API or ML runtime dependency.

## Data model (implemented)
`review(id, reps, lapses, interval, ease, due)`; `history(id, word, grade, day)`; `book(id, name, kind, page, version)`; `quiz(id, correct, total, day)`; preferences: level/date/minutes/theme. Word records from original TSV with stable IDs, translations, readings, examples. Voice PCM RAM only; no persistent attempt analytics. Files saved by generated UUID; no original path used. PDF capped 150 MiB, TXT 2 MiB. DB work, import and audio off main thread except initial tiny TSV load.

Use FKs, indexes on foreign keys, version/level and due dates; separate user DB and replaceable signed content packs; never store PCM blobs in SQL. Migration tests before schema upgrade.

## Speech decision
AudioRecord PCM 16 kHz mono -> 40 ms frames/10 ms hop -> RMS gate -> cumulative mean normalized difference -> first local minimum (threshold .18) -> parabolic interpolation -> F0 65–550 Hz -> time normalization, semitones relative to utterance median -> qualitative shape hint. Template is schematic, not measured native audio. No calibrated confidence or classifier; voiced fraction is data coverage, not accuracy. Third tone feedback only for isolated syllables; neutral tone no fixed template. Basic sandhi code takes already disambiguated lexical tones and explicit prosodic groups. Multi-third-tone grouping, Yi exceptions, contextual neutral tones and forced alignment remain pending.

Alternatives: pYIN probabilistic smoothing, CREPE neural pitch estimation (model size/runtime/license to verify), Praat/Parselmouth research baseline (not selected for APK), DTW for aligned contours (requires measured references), Vosk/Whisper for ASR only (not pronunciation assessment), Mandarin phoneme forced alignment + GOP for consonants/vowels (model and validation required). Compare against expert labeled learner corpus, not ASR match. For individual voice-range normalization use calibration across multiple reference utterances; current median normalization is per recording only. Measure octave errors, F0 error, voicing F1, tone confusion, coverage, subgroup performance and calibration before scoring. AISHELL licensed candidates are native speech, not sufficient learner-error gold labels.

## UI system
Material 3, teal primary, warm gold tertiary, light/dark/system; five bottom destinations; cards and contextual flows; clear unknown/empty and error messages. No visual verification yet. Android localization and accessibility tests pending.
